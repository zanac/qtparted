QtParted 1.0.2 is a bug fix update to [1.0.1](https://github.com/zanac/qtparted/releases/tag/v1.0.1).

## Fixes

- **Changing the UUID of an ext4 file system no longer fails** once it has been mounted. With `metadata_csum` (the default on ext4 for years) and no `metadata_csum_seed`, `tune2fs -U` rewrites every checksum and refuses unless the file system was checked after its last mount. QtParted now runs `e2fsck -f` first in that case, as tune2fs asks.
- **No more transient "unknown" file systems after a scan.** libparted opens the disk read-write to read the partition table; when it closes it, udev re-reads the partitions and briefly removes and recreates their device nodes. Partitions are now probed only after udev has settled, and read straight from the disk if a node is still missing. Opening and closing LUKS volumes also waits for udev, so a close right after an unmount no longer hits "device busy".

Both problems showed up as intermittent failures of the LUKS tests on the real kernel of the CI runners. The tests now reproduce the ext4 case on every run, and test failures appear as annotations on the CI page.
